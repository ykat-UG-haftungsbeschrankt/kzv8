# Accepted Runtime Behavior

## Address-Derived IDs

The current trusted runtime intentionally exposes address-derived values as opaque IDs:

- Timer IDs are `KernelObjectRef` identities of heap-allocated timer objects and are returned to runtime code for cancellation.
- Readiness event IDs derive from the address of their `EventSignal` allocation and are exposed as `event.id` by the V8 bridge.
- `getpid` returns the address-derived identity of the current `Process` allocation.
- `gettid` returns the address-derived identity of the current thread object.

These values are correlation tokens only. They are not secrets, authorization credentials, or stable identities across object lifetimes. Consumers must not dereference them or rely on their numeric representation.

Timer IDs have no generation component. Once a timer fires or is canceled, its heap allocation is freed; an allocator may reuse that address, so a stale ID can alias a later timer. Under the current trusted-runtime contract, callers must discard a timer ID after its timer fires or is canceled and must not use stale IDs. This reuse behavior is accepted for the current implementation.

This is a runtime-specific exception to the general object-identity guidance in `AGENTS.md` and assumes scripts using these interfaces are trusted. The numeric values are opaque IDs, never pointers to dereference. If untrusted scripts or processes are introduced, revisit this decision before exposing them: use opaque generation-checked handles and do not disclose kernel addresses to those callers.

## Kernel Audit Backlog

Work these items from top to bottom. Check an item off only after its behavior is implemented and validated. Build and QEMU validation are currently gated by `AGENTS.md` and need an explicit request.

### P1: Correctness and Isolation

- [x] **K-01: Per-thread x86 syscall stack.** `SYSCALL` switches to the per-CPU stack pointer in `gs:[0]`, but it is set when entering userspace rather than when a suspended userspace thread is resumed. After a context switch, a syscall may use another thread's kernel stack. Update the per-CPU syscall/TSS stack state whenever scheduling a userspace thread, and cover switching between two suspended syscall contexts. See [x86 syscall entry](kernel/arch/x86_64/syscall.rs) and [thread switching](kernel/scheduler/thread.rs). **Fixed: 2026-11-11** (static checks only; build/QEMU validation pending).
- [x] **K-02: Per-process address spaces.** Each `Process` now owns a user address space with a private page-table root, per-process sparse VMA metadata, scheduler root switching, user-pointer validation, lazy faults, and teardown. User virtual arenas may overlap across processes without sharing mappings. **Fixed: 2026-11-11** (static checks only; build/QEMU/smoke validation pending). See [process state](kernel/process.rs), [user VM](kernel/scheduler/thread/vm.rs), [architecture roots](kernel/arch/mod.rs), and [kernel virtual memory](kernel/memory/virtual.rs).
- [x] **K-03: Cross-CPU TLB invalidation.** x86 mapping, permission, and unmap operations now issue acknowledged APIC NMI shootdowns; each online CPU reloads CR3 and publishes its observed generation before backing pages can be reused. AP startup flushes locally before joining the online set, and VMX handles shootdown NMI exits before resuming the guest. **Fixed: 2026-11-11** (static checks only; build/QEMU validation pending). See [x86 paging](kernel/arch/x86_64/paging.rs), [x86 interrupts](kernel/arch/x86_64/interrupts.rs), and [SMP startup](kernel/arch/x86_64/smp.rs).
- [x] **K-04: Block timeout and shared-buffer ownership.** A timed-out `BlockClient` request now retains its `CallTicket` and keeps `request_active` set. Later requests return `Busy` until the worker's reply is observed, so the shared DMA buffer cannot be reused while the worker may still access it. **Fixed: 2026-11-11** (static checks only; build/QEMU/smoke validation pending). See [block client](kernel/block/service.rs).
- [x] **K-05: Bound network memory growth.** TCP now caps socket count, listener backlog, per-socket send bytes, and aggregate queued send bytes with partial-send/`NoBufs` backpressure. UDP caps socket count and receive datagrams/bytes per socket and globally, dropping new datagrams at quota. Unresolved TCP, UDP, and forwarded-IPv4 queues share entry and byte limits; routed UDP reports `NoBufs`, while TCP/forwarded packets are dropped when full. ARP neighbors and tunnel peers are capped and expired entries are pruned on updates. **Fixed: 2026-11-11** (static checks only; build/QEMU/unit-test validation pending). See [TCP connections](kernel/net/tcp/connection.rs), [UDP sockets](kernel/net/udp.rs), and [IPv4 stack queues](kernel/net/stack.rs).
- [x] **K-06: Finish TCP reliability and security.** Active and passive connections now use hardware-random ISNs (TCP open fails with `NoSys` if the architecture has no hardware RNG). Receive reassembly is bounded by the advertised window and segment-count limit, handles cumulative/partial ACKs, and delays FIN until contiguous. The sender supports a bounded multi-segment flight, ACK-based slow start/additive increase, and RTO reduction. An in-memory two-endpoint handshake/data/ACK wire test was added. **Implemented: 2026-11-11** (static checks only; unit/QEMU and independent-stack interoperability runs pending; do not treat as general-purpose TCP yet). See [TCP connection state](kernel/net/tcp/connection.rs) and [architecture random source](kernel/arch/mod.rs).

### P2: Kernel Interfaces and Lifecycle

- [x] **K-07: Process IDs at the syscall ABI.** `getpid` now returns the address-derived identity of the current `Process`, matching internal `Process::id()`. This is an opaque identity, not a namespace-local numeric PID, and follows the trusted-runtime address-ID policy above. **Fixed: 2026-11-11** (static checks only; build/QEMU/unit-test validation pending). See [getpid](kernel/syscall/fn/getpid.rs) and [process state](kernel/process.rs).
- [x] **K-08: Make namespaces enforce isolation.** Documented `NamespaceSet` and `NamespaceKind` as identity/sharing scaffolding, not a security or isolation boundary. Distinct namespace tokens do not currently scope PID reporting, VFS/mount lookup, networking, IPC, UTS data, or user-namespace mappings. **Documented: 2026-11-11** (no runtime behavior change). See [namespace sets](kernel/namespace.rs).
- [x] **K-09: Connect VFS objects to syscall descriptors.** `Process` now allocates descriptors from 3 and maps them to owned `FileHandle` objects; `openat(AT_FDCWD)` opens existing files with read-only, write-only, or read-write access, and `read`, file-descriptor `write`, and `close` use the process descriptor table. VFS futures are cooperatively polled without holding descriptor spinlocks across scheduler switches. Create/truncate flags, directory-relative `openat`, and `lseek` are not implemented. **Implemented: 2026-11-11** (static checks only; build/QEMU/unit-test validation pending). See [syscall dispatch](kernel/syscall/mod.rs), [file syscalls](kernel/syscall/fn/openat.rs), [process descriptors](kernel/process.rs), and [VFS operations](kernel/vfs/mod.rs).
- [x] **K-10: Timer IDs use address identity.** Each timer is held by `Arc<Timer>` and identified with `KernelObjectRef::from_arc`; no timer-specific ID wrapper, base-offset lookup, or generation field is used. Once the timer is freed, the allocator may reuse that address, so stale-ID aliasing remains intentionally accepted under the trusted-runtime policy above. **Accepted: 2026-11-11** (static checks only). See [timer IDs and cancellation](kernel/event/timers.rs) and [KernelObjectRef](kernel/process.rs).
- [x] **K-11: Make file append atomic.** Append-mode `FileHandle::write` now calls the atomic `FilePlugin::append` contract instead of querying size before a separate `write_at`. VirtioFS uses a per-inode async lock shared with positional writes while selecting EOF and writing, and returns the resulting file offset. Plugins without atomic append support return `NoSys`. **Implemented: 2026-11-11** (editor diagnostics and whitespace checks only; build/QEMU/unit-test validation pending). See [VFS file writes](kernel/vfs/mod.rs) and [VirtioFS writes](kernel/driver/virtio/fs.rs).
- [x] **K-12: Add TLB/page-table reclamation.** Runtime x86_64 and AArch64 page tables now use identity-mapped frames reserved from the physical allocator before taking the paging lock; the 128-entry static pool is retained only for allocator bootstrap and its pinned scratch hierarchy. Unmapping prunes empty tables in private user branches after TLB invalidation, and address-space teardown detaches and releases its page-table tree outside the paging lock. Shared kernel branches remain pinned. **Implemented: 2026-11-11** (editor diagnostics and whitespace checks only; build/QEMU/unit-test validation pending). See [x86 page-table storage](kernel/arch/x86_64/paging.rs), [AArch64 page-table storage](kernel/arch/aarch64/ram_map.rs), and [physical allocator](kernel/memory/physical.rs).

### P2: Network Scaling and Coverage

- [x] **K-13: Index hot network lookups.** Capability slots now use a free-index stack. UDP demultiplexing uses sorted exact local/connected-flow buckets with wildcard probes; TCP uses a sorted exact-flow index and listener-port buckets, rejects duplicate active 4-tuples, validates RST and ACK sequence/window state, and reaps closed passive children; socket handles remain generation-checked. IPv4 routes use sorted buckets by prefix and longest-prefix-first lookup. **Implemented: 2026-11-11** (editor diagnostics and whitespace checks only; build/QEMU/unit-test validation pending). See [capability table](kernel/process.rs), [UDP demultiplexing](kernel/net/udp.rs), [TCP flows](kernel/net/tcp/connection.rs), and [route lookup](kernel/net/stack.rs).
- [x] **K-14: Remove fixed vSwitch peer/ring capacities.** The vSwitch now grows its peer vector and peer/host frame queues dynamically, bounded by a 256-peer quota, 256 KiB per peer, 2 MiB per host queue, and 16 MiB total queued frame bytes. Its drop counter records quota/allocation failures, oversized input frames, TAP injection failures, peer teardown drops, guest RX buffers too small for a queued frame, and permanent host TX errors; frames are retained when the VirtIO TX queue reports `Busy`. **Implemented: 2026-11-11** (editor diagnostics and whitespace checks only; build/QEMU/unit-test validation pending). See [VM vSwitch](kernel/vm/device/virtio/net.rs) and [host network polling](kernel/net/stack.rs).
- [x] **K-15: Complete network protocol coverage.** The supported contract is documented as Ethernet/ARP with IPv4, TCP, UDP, and ICMP echo/errors; local IPv4 fragments are reassembled with limits of 16 datagrams, 64 pieces per datagram, 1 MiB buffered data, and a fixed 30-second lifetime reclaimed during network polling. Egress fragments to Ethernet or the 1500-byte TUN MTU when DF is clear; DF-set oversized forwarded packets receive ICMP fragmentation-needed with the selected egress MTU. IPv6, DHCP/DNS services, NAT, and raw sockets remain unsupported; socket creation returns explicit unsupported family/type/protocol errors and unknown local IPv4 protocols receive ICMP protocol-unreachable. **Implemented: 2026-11-11** (editor diagnostics and whitespace checks only; build/QEMU/unit-test validation pending). See [fragment reassembly](kernel/net/ipv4_fragments.rs), [IPv4 parsing and fragmentation](kernel/net/wire.rs), [host packet dispatch](kernel/net/stack.rs), and [POSIX sockets](runtime/libc/network.rs).
- [x] **K-16: Unify packet egress and ingress dispatch.** Ethernet and TUN IPv4 ingress now share local protocol dispatch. TCP, UDP, ICMP, and forwarded IPv4 packets serialize to IPv4 packets and use one route/tunnel/neighbor/ARP queue, one Ethernet emitter, and bounded ARP retries with exponential backoff and failed-queue cleanup. TUN-bound traffic never falls back to Ethernet when its source interface is down; limited/directed broadcasts bypass TUN routes and are not forwarded. Host TX frames remain queued on VirtIO `Busy`, while permanent TX errors are counted as drops. ARP retains its protocol-specific serializer. **Implemented: 2026-11-11** (editor diagnostics and whitespace checks only; build/QEMU/unit-test validation pending). See [network stack](kernel/net/stack.rs), [host TX queues](kernel/vm/device/virtio/net.rs), and [TUN descriptors](runtime/libc/network.rs).
